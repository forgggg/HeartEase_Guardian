调度架构说明

帮助新成员快速理解：主智能体如何调度学生画像智能体和学业问题研判智能体，并与外部问典、烽火协作，最终形成可追溯的结构化结果。

第一阶段 MVP单学生 · 单学期同步串行编排2026-11-18

1. 一句话说明

学海由一个主智能体调度两个内部子智能体，完成单学生、单学期的学业分析。

画像智能体负责看清现状；研判智能体负责判断问题；问典和烽火是学海外部模块。
校验请求 → 生成调度计划 → 校验权限 → 读取学业数据
→ 画像智能体生成画像 → 识别确定性问题
→ 调用外部问典和烽火 → 研判智能体形成结论与建议
→ 保存结果 → 写入审计 → 返回调用方

当前流程在一次 HTTP 请求内同步完成，没有使用 Celery、Redis 或 LangGraph。

4. 当前调度流程

核心调度位于 AcademicService.analyze()。

请求校验

Pydantic 校验单学生、学期格式、任务类型和建议数量。

生成计划

规则调度器确定学生、学期、关注数据和外部调用开关。

权限校验

确认辅导员可以访问目标学生，否则记录审计并返回 403。

幂等检查

权限通过后读取缓存；跨学生或学期复用 request_id 返回 409。

读取事实

获取学生、课程、成绩、考勤、学分及补考重修记录。

生成画像

画像智能体组织指标、趋势、风险课程、来源和缺失项。

问题识别

执行四条技术规则，返回 hit、miss 或 unknown。

查询问典

根据指标查询制度及其版本、时间和来源。

调用烽火

发送事实、问题和制度，接收正式预警结果。

问题研判

研判智能体基于画像、问题、制度和预警形成结论与建议。

组装响应

形成 completed 或 partial 的固定结构结果。

保存评估

写入 assessments.json，确保重复请求不重复执行。

审计返回

写入最小化审计摘要，然后返回主智能体。

关键 HTTP 行为

情况结果
请求字段非法HTTP 422
无访问权限HTTP 403
学生不存在HTTP 404
request_id跨任务复用HTTP 409
关键学业数据全部不可用HTTP 503
部分数据或外部服务失败HTTP 200，业务状态 partial

5. 画像、规则和研判边界

程序计算的指标

本学期与上学期平均分、成绩变化、挂科数、核心课挂科数、缺勤、迟到、已获与应获学分、学分缺口、学分完成率、补考和重修数量。

当前确定性规则

问题Mock 技术阈值
多门课程不及格failed_course_count >= 2
考勤异常absence_count >= 5
学分进度落后credit_completion_rate < 0.85
成绩明显下降average_score_change <= -10
这些阈值属于第一阶段技术配置，不代表正式学校制度。正式制度必须由问典返回。

学生画像智能体

  • 输入通过权限校验的可信学业事实；
  • 使用确定性 Python 工具计算指标；
  • 输出画像、趋势、风险课程、来源和缺失项；
  • 不查询制度、不判断预警、不生成处置结论。

学业问题研判智能体

  • 只接收画像、确定性问题、问典制度和烽火预警；
  • 生成摘要、待核实假设、约谈问题和最多三条建议；
  • 不得重算画像、伪造制度、修改烽火等级或把推测写成事实。
当前两个子智能体分别使用规则和程序模板实现，尚未安装或调用 LangChain。

9. 当前限制与上线前事项

  1. 数据源、问典和烽火当前使用 Mock；两个子智能体当前为规则/模板实现。
  2. 只支持单学生、单学期，不支持班级批量扫描。
  3. 同步串行调度会受到外部服务响应时间影响。
  4. 本地 JSON 存储不适合多实例并发部署。
  5. 当前幂等冲突校验学生和学期；正式环境可进一步保存完整请求指纹。
  6. 真实 HTTP Adapter 及其超时、重试尚未实现。
  7. failed 已预留，但关键失败目前主要通过 HTTP 错误返回。
事实由数据源提供 · 画像由画像智能体组织 · 问题由确定性规则识别
制度由外部问典提供 · 预警由外部烽火决定 · 研判结果由辅导员最终复核
